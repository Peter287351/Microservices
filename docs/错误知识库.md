## 模块 00：项目脚手架（2026-08-29）

### E00-1 Docker 端口冲突：`ports are not available: bind: 0.0.0.0:3306`
- **现象**：`docker compose up -d` 后 MySQL 容器立刻退出，报 `Only one usage of each socket address`
- **原因**：宿主机 3306 已被本机原有的 Windows MySQL 服务（mysqld.exe）占用
- **排查**：
  ```bash
  netstat -ano | findstr 3306        # 找到 LISTENING 行末尾的 PID
  tasklist /FI "PID eq 6852"         # 确认进程身份
  ```
- **解决**：端口映射改为 `3307:3306`，JDBC URL 同步改为 `localhost:3307`；不动本机已有服务
- **预防**：启动容器前先 `netstat -ano | findstr <端口>`；记牢映射格式是"宿主机:容器"

### E00-2 `java -jar` 报"没有主清单属性"（no main manifest attribute）
- **现象**：jar 能打出来（仅几百 KB），运行即报错
- **原因**：自定义父工程（非 spring-boot-starter-parent）时，`spring-boot-maven-plugin` 的
  **repackage 目标不会自动执行**，打的是普通瘦 jar，缺 `Main-Class`
- **解决**：父 pom 的 pluginManagement 里给该插件显式加：
  ```xml
  <executions><execution><goals><goal>repackage</goal></goals></execution></executions>
  ```
- **验证**：fat-jar 应为几十 MB（依赖全打包在内）
- **教训**：**不用官方 parent 时，它默认替你做的事都要自己补**——这是自定义父工程第一坑

### E00-3 接口 500：`parameter name information not available via reflection`
- **现象**：`GET /users/1` 返回 500；日志提示 `Ensure that the compiler uses the '-parameters' flag`
- **原因**：`@PathVariable Long id` 未显式写名字时，Spring 6.1 需要反射读取方法参数名；
  编译器默认丢弃参数名信息（Spring Boot 3.2 / Framework 6.1 移除了旧的字节码兜底解析）
- **解决**：父 pom 加 `<maven.compiler.parameters>true</maven.compiler.parameters>`
- **预防**：或给注解显式写名字 `@PathVariable("id")`；两者都做最稳
- **典型场景**：老项目从 Boot 2.x 升 3.x 时大批接口突然 500，就是这个

### E00-4 Windows curl 发中文 JSON：`JSON parse error: Invalid UTF-8 start byte 0xbb`
- **现象**：含中文的 POST 请求 500，纯英文正常；服务端 Jackson 解析失败
- **原因**：Windows 控制台默认 **GBK** 编码，命令行参数里的中文以 GBK 字节发出，
  服务端按 UTF-8 解析（0xbb 正是"机"字 GBK 编码首字节）
- **解决**：中文请求体先存为 UTF-8 文件再发：
  ```bash
  printf '{"productName":"机械键盘"}' > order.json     # Git Bash 的 printf 输出 UTF-8
  curl -X POST ... -H "Content-Type: application/json; charset=utf-8" --data-binary @order.json
  ```
- **预防**：接口测试用 Postman/Apifox；或服务部署时统一 `-Dfile.encoding=UTF-8`

### E00-5 缺参数/请求体解析失败被兜底成 500（应为 400）
- **现象**：`GET /orders` 不带 `userId` 返回 `{"code":500,"message":"系统内部错误"}`
- **原因**：Spring 抛出的 `MissingServletRequestParameterException`、
  `HttpMessageNotReadableException` 落入兜底 `Exception` 处理器
- **解决**：`GlobalExceptionHandler` 为这两个异常单独加 `@ExceptionHandler` → 400 + 明确提示
- **经验**：**500 只留给未知异常**；可预见的客户端错误一律 4xx，这是排障判断"锅在前端还是后端"的关键信号

### E00-6（预防型）服务连不上数据库：`Communications link failure`
- **排查三连**：
  1. `docker ps` 看 micro-mysql 是否 `healthy`（不是 running 就够）
  2. JDBC URL 端口是 **3307**（映射后的），不是容器内部的 3306
  3. 密码与 docker-compose.yml 的 `MYSQL_ROOT_PASSWORD` 一致

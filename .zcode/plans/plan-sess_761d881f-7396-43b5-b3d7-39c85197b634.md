# Java 微服务学习计划 —— 从零构建电商微服务系统

## 一、已确认的需求
- **技术栈**：JDK 17 + Spring Boot 3.2.4 + Spring Cloud 2023.0.1 + Spring Cloud Alibaba 2023.0.1.0（官方兼容组合）
- **中间件**：全部用 Docker Compose 运行（Nacos、Sentinel、Zipkin、RocketMQ、Seata、MySQL）
- **代码组织**：单一 Maven 多模块工程持续演进；每个学习模块建一个独立子文件夹，只放该模块的教程文档（概念/链路/问题/实践/考题）
- **Git**：本地 git init + 指导你在 GitHub 创建远程仓库并推送；每完成一个模块提交一次

## 二、最终项目结构（随模块逐步长成）
```
Microservices/
├── pom.xml                      # 父工程：统一管理三个 BOM 依赖版本

├── .gitignore

├── common/                      # 公共模块：统一返回 Result、异常、DTO
├── user-service/   (8081)       # 用户服务：JPA + MySQL，GET /users/{id}
```

## 三、学习路线（每模块一个 git 提交，前缀 feat/docs）
| # | 模块 | 核心产出 |
|---|------|---------|
| 00 | 项目脚手架 | 父 pom、common、user/order 两个纯 Boot 服务、MySQL 容器、GitHub 建仓推送 |
| 01 | Nacos 注册中心 | docker 加 Nacos，两服务注册发现，服务列表查看 |
| 02 | Nacos Config | spring.config.import 接入配置中心，@RefreshScope 动态刷新 |
| 03 | OpenFeign | order-service 声明式调用 user-service（下单时校验用户） |
| 04 | LoadBalancer | user-service 双实例演示轮询/权重，自定义负载策略 |
| 05 | Gateway | 网关路由、断言、过滤器，统一通过 8080 访问 |
| 06 | Sentinel | 限流规则、@SentinelResource、熔断降级、fallback |
| 07 | 链路追踪 | Micrometer Tracing + Zipkin，看完整下单调用链 |
| 08 | Stream+RocketMQ | 下单成功发"订单创建事件"，异步消费解耦 |
| 09 | Seata | AT 模式分布式事务：下单+扣库存跨服务回滚 |
| 10 | Security+JWT | 授权服务器、令牌签发校验、网关统一鉴权 |
| 99 | 综合实战 | 全链路：网关→鉴权→下单→Feign→Seata→MQ |

**每个模块的 README 均按你要求的 6 部分编写**：①项目背景（在本电商系统中的定位）②概念文档（通俗讲解+ASCII 架构图）③"下单"请求链路分析（流转路径/数据交互/代码调用点/易错点）④3-5 个常见问题与排查思路 ⑤动手实践（集成步骤+demo 验证+git 命令与提交说明）⑥3 道检查题。

## 四、本次执行范围（第一次会话就完成模块 00）
1. **环境检查**：确认 java/mvn/git/docker 可用及版本；若缺 JDK17 或 Maven 则先给安装指导
2. **编写总计划文档**：根目录 README.md（学习路线图、进度打卡表、每模块学习节奏：讲解→集成→验证→提交→考题→评分→建议）、.gitignore（Maven/IDEA）
3. **git init 并首次提交**：`docs: 制定微服务学习计划`
4. **搭建模块 00 代码**：父 pom（三个 BOM dependencyManagement）、common 模块、user-service（8081，用户查询/创建接口）、order-service（8082，下单接口，暂不远程调用——留到模块 03）、docker-compose.yml（MySQL 8.0，数据库 micro 及初始化脚本）
5. **构建验证**：mvn 编译通过，指导启动两个服务并用 curl 冒烟测试
6. **GitHub 指导**：创建远程仓库 → 配置 SSH key → git remote add → push，提交信息 `feat(module-00): 搭建微服务项目脚手架`
7. **模块 00 考题**：出 3 道检查题，根据你的回答给后续建议

## 五、后续节奏
每次会话推进一个模块：我编写该模块 README + 修改工程代码 + 更新 docker-compose + 编译验证 → 你动手运行 demo、回答考题 → 我批改并给建议 → git 提交推送，进入下一模块。
